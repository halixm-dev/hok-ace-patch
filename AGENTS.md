# HOK ACE Mobile English Patcher

Windows GUI that installs the English or Indonesian translation into 王者万象棋 (`com.tencent.tmgp.osgame`) on an Android phone over USB, without root. The Android app in `android/` runs the same pipeline on the phone through Shizuku.

Python **3.12 only**. `resources/runtime/` is 3.12 bytecode and will not load on any other version.

## Commands

Run from the project root:

```bat
setup.bat      :: .venv + requirements.txt  (fallback: set PYTHON=C:\path\to\python3.12.exe first)
build.bat      :: -> dist\HOK ACE Mobile English Patcher.exe
run.bat        :: run from source
```

Headless runtime check (needs a dumped game directory):

```bat
dist\HOK ACE Mobile English Patcher.exe --selftest <game-dir> <out-dir>
```

No test suite. Verify changes with `run.bat` or `--selftest`. The texture codec has its own offline check, which needs neither a device nor a game dump:

```bat
.venv\Scripts\python.exe tools\research\check_graphics.py [--game <game-dir>]
```

The whole pipeline also runs offline against a dumped game directory. Add the cached APK to include content that exists only inside it. The builder is optional and needed only when `REBUILD_PACKAGES` names a package:

```bat
.venv\Scripts\python.exe tools\build_device_patch.py --runtime resources\runtime --game <game-dir> ^
    --catalog resources\catalog --work <work-dir> --output <out-dir> ^
    --apk <path>\installed.apk
```

## Architecture

| Path | Role |
|---|---|
| `app/` | GUI (`hok_patcher.py`), device workflow (`patcher_core.py`), APK rewrite + v2 signing (`apk_tools.py`) |
| `tools/` | Translation build pipeline: patch languages (`languages`: catalog per language, English payload fallback, token terms, glossary), keyword glossary applied to the catalog as it loads (`terminology`), text staging (`build_device_patch.build_patch`), prime rebuild (`package_rebuild`, `qts_builder`), append into an existing package (`qts_insert`), texture pass (`device_extensions.port_graphics`; a regioned atlas is placed by the device's own sprite table, `sprite_table`), extra-text pass (`extra_text`, `pb_text`, `unity_text`), ASTC/Oodle codec (`mobile_graphics`), shard relocation (`qts_relocate`) |
| `tools/research/` | Reverse-engineering probes and the offline graphics check; never imported by the app or the pipeline |
| `resources/runtime/` | Compiled `wxq_patch` translation runtime (from the PC patcher) |
| `resources/catalog/` | English translation catalog (`catalog.json.gz`) plus the English texture payloads (`.blocks` / `.assets`) the texture pass applies |
| `resources/catalog_id/` | Indonesian catalog: its own `catalog.json.gz`, and only the textures it re-draws (`<HASH>.blocks` + `previews/<HASH>.png`); every other payload is read from `catalog/` |
| `resources/sprites/` | This repo's own art for regioned atlases, read beside the catalogs by every language: `<HASH>/labels/` (renders for sprites the catalog never translated) and `<HASH>/restore/` (pristine crops of the sprites the old offset port overwrote) |
| `resources/qtsvfs/` | Tencent's own package builder (`QtsVFS.dll` + `QtskDB.dll` + VC runtimes), driven by ctypes to lay out a package whole |

Flow: `patcher_core` drives the seven device steps and calls `build_patch`. `apk_tools` rewrites and re-signs the APK. The GUI talks only to `patcher_core`.

`sys.path` is set in `patcher_core.py`: `tools/` is inserted for source runs; `resources/runtime/` is **appended** so the project stdlib wins.

### Staging contract

The staging summary contract (payload fields, `mode` values, skipped lists, pass order, APK/builder gating) is the `build_patch` docstring in `tools/build_device_patch.py`.
Read it before editing the pipeline, and change it in the same edit as the code; `tools/research/check_staging_contract.py` checks it stays there.

## Constraints

- Write the translation **after** the in-game update finishes. Tencent's updater applies binary diffs that break if language packages were modified inside the APK.
- `resources/runtime/` is precompiled bytecode — treat it as binary. When the runtime needs an extra stdlib import at freeze time, add it to `HIDDEN_IMPORTS` in `app/build_exe.py`.
- Coverage is **the staged text tables, the catalog's textures, and one hard-coded Lua label (`extra_text.SCRIPT_LABELS`)**: no other text tables, and no graphics beyond the reviewed edits in `resources/catalog/` and the two Career-atlas labels this repo draws itself (`mobile_graphics.ATLAS_LABELS`: MY SKINS, TOTAL PROFIT). The `extra_text` config-asset allowlist, `SAFE_ASSETS`, is device-gated and **empty**: every asset ever cleared was later withdrawn. Translating task names `5214339F97C419ED` makes a tournament replay SIGSEGV, the four chessplayer-skill assets remove the skill-description button, mail/quiz/notices remove the game button and blank the encyclopedia, the rule pages `B5D856BFDF22400D` (`ResHelpSystemCfgDataBin`) remove the Announcement screen's back arrow and title, and the nicknames / display-text table / compliments (`2D1113B0AD51A562`, `A1987F488164E53A`, `1C8F7FFF7BDEF14D`) make every match end in the client's QTS-failure popup, `/未翻译UI/QTSFailureTips` (device-measured 2026-10-05; the 10-01 verdicts that had cleared them watched the replay only), and the prime-only card-pack covers `9E45602F1857539D` empty Diamond Frenzy's Starting Lineup grid (2026-10-16). `SCRIPT_LABELS` is the one exception and is not a config bin: an exact literal in a Lua UI script (`9BD30F0DF58B1FBF`, the Effect Card filter's `通用`), replaced with the catalog's translation and carried by the append because the script is prime-only; it was device-verified on its own screen and across a match. The withdrawn hashes and their symptoms are recorded in `tools/extra_text.py`; never add to that set without a device cycle, and never treat "the staged package did not change this asset" as "the asset was disabled". The fifteen assets the note calls *not tried* are the same rule's other half and are now a measured queue, `extra_text.CANDIDATE_ASSETS`: `--cycle-asset <hash>` enables exactly one of them for one run, `device_patch_summary.json`'s `cycle_assets` records which, and the hash moves into `SAFE_ASSETS` only after the verdict — with the screen written beside it when it fails. `tools/research/extra_text_candidates.py` reprints the queue's measurement against a dump and checks that a run naming no candidate plans the allowlist and nothing else; run it before ordering cycles rather than trusting the note, whose short eight-digit forms are prefixes of the hashes the packages carry. No heuristic replaces that cycle: the source fork's row-checksum test (`pb_text.has_row_checksum`) answers true for the withdrawn bins *and* for the four the allowlist used to translate on a freshly pulled layer — all of them are ResData config bins — so it was measured and dropped, and the allowlist stays the only gate. Measure this class of question on the pristine layer: our own rewrite invalidates a bin's stored MD5, so a copy this project has already written to answers the opposite way. Do not describe the result as a complete translation. State the texture count as *applied*, never as *covered*, and check **both** data layers before calling an edit unreachable: of the catalog's 398 texture edits, 395 exist in the mobile build under their own hash — 323 in the downloaded layer, 73 inside the APK, one of those in both — and `197CC5393D16E3CB`, `884E0B4581F47CF7` and `89C771ECFCDC7FBE` exist in neither. Those three are effect-card band edits whose cards the mobile build carries under other hashes; `mobile_graphics.DEVICE_REVISIONS` maps each to the one package-`15` card whose band matches the edit's group at a mean difference of 0.01-0.02 (next closest 0.38, a blank band), so a run applies all **398** (`884E0B4581F47CF7` is the Riverlands card Armed Power, device-verified 2026-10-05). An alias joins that table only on such a measurement, never by guess. `7B4CC5DF48336D2D` exists only in the APK's package `21` and reaches the phone by **append** (`qts_insert.add_assets`: one record added to `21`'s override copy, whose container shape is untouched), which is why that package no longer needs a rebuild. Rebuilding `21` also applies it and the game mounts it, but on the phone it makes the Factionless card Yixing draw as the game's grey placeholder, so `21` stays out of `REBUILD_PACKAGES`. Since `REBUILD_PACKAGES` was emptied, packages `1` and `1050016095` reach the phone the same way — 297 of `1`'s 298 prime-only tables and all 71 of `1050016095`'s prime-only textures — and no package is laid out again. **The text pass stages the catalog's tables and nothing else.** `adaptive.scan` recognizes a localization table by shape and can resolve one the catalog has no `.blocks` for, so it would stage a table outside `catalog.known` — while the rebuilt path, which consulted `catalog.known` alone, would not, so the two paths disagreed about the same layer. `build_device_patch._drop_uncatalogued_tables` drops what the catalog does not list, which is what keeps "nothing is translated outside the catalog without a watched cycle" true; `counts` in the summary is adjusted with it. On this data that is exactly two assets of package `1`: `3914DBBFECD1E54D` (one row, `高光表情`) and `63922EF4D4C86526` (three, `幻化`/`夺宝`/`限时`). `3914DBBFECD1E54D` cannot be cycled at all — a sweep of all 277 packages finds its key referenced by exactly one asset, a 日月行者 draw-type row windowed 2025-09-10 to 2025-10-10, so no live screen can draw it — and it stays Chinese the way any catalog miss does; `63922EF4D4C86526` is reachable and joins `SAFE_ASSETS` if a cycle clears it. Its size is not the reason — a rebuild lays out the *downloaded* copy, 4866 assets and about 40 MB, not the APK's 511 MB over 85 211 assets, so a future attempt should be judged on what it costs the screens, not on recompression. An earlier count of 75 was measured against the downloaded dump alone, so a search for a missing asset must cover `assets/bin/Data/Package/builtin/` too; `tools/research/prime_probe.py` is that census. `{Energy}`/`{LordExp}`/`{LordHp}` are expanded to the patch language's terms in the staged replacements (`tools/resource_tokens.py`; the per-language table is `languages.Language.resource_terms` — Indonesian writes `EXP Chessplayer` / `HP Chessplayer`, the order its catalog uses). The catalog must keep the tokens: `translate_table` requires matching placeholders, so expanding the catalog instead trips `placeholders_changed` and drops the records. The same expansion has to be applied to the assets the prime-rebuild and extra-text passes translate, which is what `resource_tokens.expand_tokens` is for.
- **One game keyword reads one way: the default name.** `tools/terminology.py` is the terminology table (`languages.Language.terms`): `夺取` is always *Steal* and `整备` always *Prepare*, in English and in Indonesian, which keeps these keywords in English. Those are the default names; *Plunder* and *Readiness* are the unofficial community translation's and are what the glossary replaces, so never point a term at the community name. `build_patch` calls `terminology.install()` before the first catalog load; it replaces `adaptive.load_catalog`, because the scanner calls that by name, and corrects `unique` and the sourced `english_updates` rows in memory before the runtime's `Catalog` is built — `catalog.json.gz` is never edited. A rule fires only when the target's **Chinese** source contains the term, rewrites only its measured English variants, and never touches a `{placeholder}`, a `<tag>` or a `keep` phrase another word of the source owns (`摄灵` → "Soul Snatch"); `translate_table` validates both, so a rule that changed one would drop the record. Add a term only with its variants measured on both catalogs and every changed pair re-validated (`docs/features/terminology-table.md` has the checks). `掠夺` is a different word and keeps its "Plunder". **Strings a data update adds** to a table the catalog covers are supplied by `tools/catalog_supplement.py`, merged by the same loader before the glossary and only where the catalog has no entry, so an upstream catalog always wins; every target must keep its source's placeholders and pass `adaptive.validate_translation`, and tiered titles and leaderboard ranks are generated from the catalog's own base names, not listed. Indonesian also writes every keyword **series** label in its own order, "Seri Prepare" / "Seri Deploy", never "Prepare Series" (the user's choice, 2026-10-16). The glossary reaches only a layer the scanner translates: a phone already patched keeps the old words until its game data is cleared.
- **A regioned atlas is placed by the device's sprite table, never by the catalog's offsets.** The catalog drew its `.blocks` patches on the PC atlas layout, and the mobile Career atlas `13C19E4E4486B31C` packs 11 of its 13 regions elsewhere, so the old offset-for-offset port wrote 9 English labels onto other sprites — `我的棋手` stayed Chinese on the Career screen while `我的皮肤` was overwritten — from the day it shipped. `sprite_table.REGION_SPRITE_ASSETS` maps each regioned atlas to the asset holding its Sprite objects; `port_graphics` reads the rects from the device's copy every run, and `mobile_graphics.port_atlas` composites each region's English into its device box, redraws the blocks the old port wrote from `resources/sprites/<HASH>/restore/`, and draws `ATLAS_LABELS`. A missing table, or a region absent or resized there, refuses the texture into `graphics_skipped` — there is no fallback to the PC offsets, which is the bug. The rebuild transform has no package to read a table from and refuses the atlas the same way. When nothing moved and there is no art to draw (the other two regioned atlases today), the output is byte-identical to the offset port. A restoration crop is used only while the device's art outside the damaged blocks still matches it (`RESTORE_MATCH_MEAN`), so a redrawn sprite is never painted over with a stale one. `tools/research/atlas_sprites.py` reprints the tables and rebuilds the art; `check_graphics.py` `[10]` and its `--game` rows check the port. **Device-verified 2026-10-10 on the Career screen** (Xiaomi M2007J3SG, game data 1.5.0.1): the labels read English at their own sprites, MY SKINS and TOTAL PROFIT included; other screens that draw the moved sprites were not walked. See `docs/features/texture-translation.md`.
- **A config bin the catalog does not cover must not be rewritten.** The client enforces the checksum such a bin stores, so rewriting one — even at identical length, even with its refs merely re-pointed — makes the game drop everything that bin feeds. Measured on the ACE encyclopedia's Talent Card grid: re-pointing the refs of `0AA59370241BFC22` emptied the grid completely (twice, once for 1811 refs and once for all 4064, both at 409,893 bytes and chunk size 307200; the grid returned when the shipped build was pushed back). That is the same failure the withdrawn `extra_text` assets record as "blank the encyclopedia", so those withdrawals are a **reseal** problem rather than a content problem, and the way to reseal one is not known here. A text table also cannot gain rows past `chunks x size - raw length`, because a new chunk needs a lookup key that is a hash of (asset, chunk index): it cannot be computed, no package carries a spare index to harvest (every candidate table's layer copy has the APK's own chunk count), and only Tencent's builder derives it, which this project excludes. Tencent's 75,605 entries declare just two chunk sizes (307200 and 16384). Our output's eleven enlarged entries can be read offline, but startup alone did not prove each dictionary resolves in the client. On 2026-10-03, a fresh control isolated the Talent Card regression to `C059EA43719099F1`: its full 4064-row English payload (313710 bytes) fails as one 315392-byte chunk and works as two chunks at the original 307200 bytes. The user authorized an offline builder diagnostic, which measured native chunk keys `15A33357ECBFA5CC` (0, matching the phone) and `29157589AC92F155` (1). `device_extensions` retains those identity keys, validates the known slot framing, and appends chunk 1 without rebuilding the container or invoking the builder on a normal run. This one measured exception adds no dictionary rows and changes no config bin. On 2026-10-08 the same failure was reported on Diamond Frenzy's Effect Cards (`#23F7...#` raw refs): every game mode carries its own copy of the card dictionary under its own ref prefix, and the relocation pass had enlarged the chunk size of the other ten (`28D9F8B02CAA94E2` and `A336359CD92A858E` at 2 chunks, eight more at 1). With the user's authorization the builder minted their native keys the same way, offline, one throwaway one-asset build per dictionary; each build reproduced every key the device already carries — the two Talent keys included — before its new keys were taken. `device_extensions.NATIVE_CHUNK_KEYS` holds all eleven, so every card dictionary keeps 307200-byte chunks and gains chunks instead. Only the Talent dictionary is device-verified so far. `repair_card_dictionaries` repairs older already-English packages too; the scanner otherwise has no replacement to stage. Unknown layouts are refused and reported rather than guessed.
- `qts_relocate.read_raw` must follow each chunk's own framing instead of the entry's compression id: stored when the compressed and uncompressed sizes agree, a Zstandard frame when the payload opens with `28 b5 2f fd`, otherwise the id's codec (`1` and `9` are LZ4 — `9` is the same LZ4 block data behind a 12-byte-longer entry descriptor — and `4` is Oodle). One asset mixes framings, and package `21` has twelve that do. Going by the id alone left 1285 of that package's 4866 entries unreadable, and `rebuild_package` refuses a whole package over a single unreadable entry, so the reader is what a rebuild of `21` would need; that rebuild is left out for the card above instead. `zstandard` is a run-time dependency for this reason (`requirements.txt`); PyInstaller reaches it through the import, as it does `lz4`.
- A rebuilt package can only carry assets that have bytes. An override entry whose chunks are in neither layer is left out and named in that entry's `entries_without_bytes`; that is a no-op for the game, which could not read such an entry either. Bytes that exist but will not decode still abort the rebuild rather than being dropped, because dropping those would revert the assets to the APK's revisions with nothing in the log to say so.
- `count_translated` returns `(text tables, textures)`. Classify on `packages[].mode == "graphics"` for the texture pass, and on the entry's own `textures` field for `mode == "rebuilt"` or `mode == "added-from-apk"`, which each hold both kinds in one entry. Keep both halves wired through the GUI. Do not report an image count without a texture pass behind it. `count_untranslated_graphics` reads `graphics_skipped` for the textures a run found but could not translate and `append_skipped` for the textures it could not add, and `count_untranslated_text` reads `text_skipped` for the tables the drop loop left out plus the tables `append_skipped` could not add; the GUI shows both, because "N translated" alone reads as "all of them".
- The append pass never rewrites anything it did not add: it appends a record to the target's shard and index and inserts one key into each B-tree, and only the tree pages, the header's data-end words and the appended records differ afterwards. `Shard.insert_key` supports one measured split: a full root leaf becomes two leaves and an internal root, using reserved page space. It raises `TreeFull` for a full leaf under an existing internal root or another unmeasured layout; `add_prime_only` catches that per package and reports it in `append_skipped` rather than failing the run, because one full leaf should not cost the whole patch. Measured headroom on Tencent's own package `21`: its override index has 12 leaves at 333–491 keys and its shard 15 leaves at 344–464, none full. `add_assets` writes `<id>_0.db` by name, so a device copy split over several shards is skipped rather than guessed at, and it reads every appended asset back through `QtsPackage` before returning — that read-back is the only check this path has, so it must not be dropped. The pass is idempotent against its own output: an asset the staged copy already holds is not appended again, because a second record would index the same B-tree key twice. That staged copy is left in place rather than deleted — it holds the earlier run's result — so an output directory that is reused across runs can hold a package the later run does not report. The app never reuses one (each run stages into its own session), which is what keeps `packages` and the directories in step in a real run.
- `package_rebuild.make_transform` exposes `transform.graphics` (the catalog's textures plus their `DEVICE_REVISIONS` aliases), `transform.tables`, `transform.scripts` (`extra_text.SCRIPT_LABELS`) and `transform.config` (`SAFE_ASSETS` plus the run's `cycle_assets`), the sets its result is decided against. `add_prime_only` uses all four to tell an asset it may append from any other one, so a new kind has to be added to `make_transform`, not only to the pass. `transform.config` is what lets a prime-only config asset reach the phone, which the in-place extra-text pass cannot, because it reads the downloaded layer; it is empty on a normal run while `SAFE_ASSETS` is, so without `--cycle-asset` the append stages exactly what it did before. Its first cycle, the card-pack covers bin `9E45602F1857539D`, was withdrawn: appended with all 60 strings translated it empties Diamond Frenzy's Starting Lineup grid (`docs/features/card-pack-covers-cycle.md`). `extra_text.extend_text` applies `SCRIPT_LABELS` to a script the downloaded layer carries, even in package `10`, which the protobuf pass otherwise excludes.
- The texture pass reads BC7/RGBA32 payloads, encodes ASTC and unpacks Oodle chunks, which needs `astc_encoder`, `ooz` and `texture2ddecoder` at run time. `wxq_patch` never references them, so PyInstaller cannot find them on its own: `app/build_exe.py` collects each one explicitly. Dropping those flags still builds a working exe that dies on the first texture.
- The prime rebuild needs `resources/qtsvfs/` (Tencent's builder) and the pulled APK, and only the rebuild needs the first: the append that carries the primed content on a normal run takes the APK alone. `build_exe.py` ships the builder with `--add-data`; the APK arrives as `Patcher.normal_apk`. Lose the APK and the run still works, it just logs that prime-only content stays Chinese — so a "successful" run is not evidence that the primed content was carried. Check the log for the `added from the APK` lines.
- `pypinyin` is needed by the extra-text pass alone (they romanise the AI opponent names, which the catalog does not translate). It carries its own dictionary data, so `build_exe.py` uses `--collect-all` rather than `--hidden-import`.
- A texture `english_raw` cannot handle returns `None` and is counted as skipped, never raised. Keep it that way: a skipped texture is better than a failed patch run. The one rescue path is `splice_label`, for a whole-image replacement whose device revision moved geometry: it copies only the label across, and refuses unless the two images actually align. It must stay idempotent — it returns its input untouched once the label matches, because re-encoding from a lossy decode perturbs the label's edge blocks.
- Code injection into the APK and prebaked APKs with translated assets both fail (anti-cheat kill / `IsPrebuild errorCode:151`). The supported path is: re-sign → debuggable data-access copy → replace packages in game data → reinstall. The debuggable copy must never stay installed: the game dies during Unity startup under it (device-measured, signal 7 bus error), so a run interrupted before the reinstall looks exactly like a patch that broke the game. `prepare_normal_apk` must therefore never cache the patcher's own access APK as the game APK — the two differ by the debug flag (and one byte of size), and a debug build adopted into the cache makes every later restore install a game that cannot start.
- The APK that stays on the phone is the game's own file with exactly one entry rewritten, `AndroidManifest.xml`: the debug flag cleared, and the app named `APP_NAME` (`Honor of Kings: ACE`, the launcher and task-switcher label, written by `tools/axml_label.py` as a literal so `R.string.game_name` keeps its Chinese value). That is the whole of our content change to the shipped APK, so any further edit there is a new class of change and needs its own device cycle. The rename is cosmetic and must stay optional: `manifest_to_install` logs a manifest it cannot read and continues, because a name must never fail the translation. The game's own manifest declares no `android:debuggable` at all (1.1.1, versionCode 774472, measured 2026-10-08), so the normal APK needs no flag edit and the access APK has the attribute inserted; Android 16 on an Infinix X6853 honours the inserted flag, and an Android 15 Infinix X6851 failed preparation on this check (see `docs/lab-notebook.md`, 2026-10-08). Both editors leave a manifest byte-identical when there is nothing to write, which is what lets a re-run skip rebuilding the cached APK, and `is_debuggable` guards the flag edit so a manifest that never declared the attribute is left alone instead of having it added. The rename lives in that cached file and nowhere else, so a cycle driven by hand has to check it before installing: `adb install -r dist/HOK ACE Patcher Data/installed.apk` while the cache still holds `@string/game_name` puts the **Chinese name back on the launcher**, and `set_label(apk_manifest(cache), APP_NAME) != apk_manifest(cache)` is the test for whether it has been renamed yet. `prepare_normal_apk` renames the cache when it finds it unnamed, so running that step — or the same rewrite by hand — is what keeps a manual cycle from reverting the name.
- Re-signing breaks direct WeChat/QQ login. Users log in via *Scan to login*. That limit is expected.
- The patcher's ~8 GB working data goes to the user-chosen folder (default `HOK ACE Patcher Data` beside the exe), never into this repo.
- `build/`, `dist/`, `.venv/` are generated and disposable.

## Boundaries

- `resources/key/` holds the re-signing key (`key.pk8`, `cert.der`) and ships with the app on purpose. Keep the key stable across releases; do not regenerate it.
- `resources/qtsvfs/` holds Tencent's own `QtsVFS.dll` and `QtskDB.dll` and ships on purpose too: it is what mints a package's lookup keys, and the frozen exe has to carry it. They are third-party binaries — treat them as immutable, and never hand-write a package layout in their place. Its keys are identity functions, measured: an entry key (record `+12`) varies only with the asset it names, and a chunk's `hash1` (slot `+12`, ordered on its low 32 bits) only with the asset and the chunk index — not with the content, the stored framing, the byte length, the chunk size or the chunk count (`tools/research/key_derivation_probe.py`; `docs/features/prime-rebuild.md`'s "The keys the builder derives" has the counts). So an asset a package already carries needs no key derived at all — it can be read out of any package holding it, which is what `qts_insert` does — and only a chunk index that does not exist yet needs the builder for a key. The builder also mints the 16 content-derived bytes at record `+52`, but nothing checks them: the shipped in-place stager rewrites content and updates only the raw length at `+44` and the chunk size at `+80`, never those bytes, measured over the 99 rewritten records of a phone-pushed run (`tools/research/key_derivation_probe.py --stager`; `docs/features/prime-rebuild.md`'s "The keys the builder derives"). A record harvested out of another package is therefore a whole record, and the append path no longer uses the builder for one: `qts_insert.add_assets` reads the record from the APK's prime copy of the package, re-encodes the payload the way `device_extensions.write_assets` does, and keeps the chunk count. Nothing in a normal run calls the builder at all today — naming a package in `REBUILD_PACKAGES` is what does, and then its output is still read back byte-for-byte.
- `resources/catalog/`, `resources/catalog_id/catalog.json.gz` and `resources/runtime/` are produced by the PC patcher pipeline. This repo consumes them. The other files in `resources/catalog_id/` are this repo's: `previews/<HASH>.png` is the re-drawn art and `<HASH>.blocks` is generated from it by `tools/research/make_language_payloads.py` (`--check` proves the shipped payloads are current), named exactly as the English payload it replaces so the catalog's own metadata applies to it. A language catalog that lacks a payload falls back to the English one (`languages.payload_path`), which is why `catalog/` must ship beside every other catalog — `build_exe.py` and `android/app/build.gradle.kts` both stage the two side by side. Never edit the catalog to fix a record: corrections belong in this repo's code, which is why `mobile_graphics.MISSING_METADATA` supplies the geometry six entries omit. The one sanctioned write is `tools/research/apply_catalog_fixes.py`: it adds the strings a game update introduced that upstream has no entry for (`tools/research/catalog_additions.json`, English and Indonesian per Chinese source), plus the Indonesian label fixes, and checks byte-for-byte that nothing else in either `catalog.json.gz` changed. Re-run it after every upstream catalog import, and extend the JSON rather than the gzip when an update leaves new strings Chinese; an addition upstream has since translated is left to upstream. Every entry must pass `adaptive.validate_translation` (tags and placeholders unchanged, no Chinese left).
- `resources/sprites/` is this repo's art. `restore/` is generated by `tools/research/atlas_sprites.py restore --pristine <pkg19> --layout <pkg19>` from a dump the patch never wrote to (`--check` proves the shipped crops are current); never hand-edit a crop, and take it from a pristine layer only, because the downloaded layer of a patched phone carries the old port's damage. `labels/` is **hand-finished art and the source of truth**: the tool's `labels --out <dir>` assembles drafts from the catalog's own English glyphs, and the user polished the shipped MY SKINS and TOTAL PROFIT by hand (2026-10-10, `tasks/T15/edit/`). Never regenerate over them; edit them in an editor that keeps alpha, keep them white shaped by alpha at the sprite's size, and run `labels --check` and `tasks/T15/validate_assets.py --delivered <dir>` before shipping a change.
- `tools/research/` is a research record, not shipping code. Nothing imports it and `app/build_exe.py` does not bundle it. Moving or deleting it must not break `app/` or `tools/`. Its scripts are run by hand from the project root.

## Docs

`docs/features/` holds one record per shipped feature: `## Report` (what landed, the verification commands and their results, the journey log of what was measured and withdrawn), `[S1] Problem`, `[S2] Design`, `[S3] Out of Scope`, and no task list (a shipped `.scratch` spec is promoted into one by the step in `docs/agents/issue-tracker.md`). This file carries the rules that always apply; a record carries the reasoning and the evidence behind them.

- `docs/lab-notebook.md` is that evidence, gathered in one place: device verdicts, asset hashes, byte counts, the coverage numbers behind the constraints, and the claims that were measured, acted on and turned out wrong. Read it when a rule's reasoning or a number is in question, and before re-running an experiment that may already have an answer. It is a record, not a rule set — where the two disagree, this file wins.

- `docs/translation-progress.md` is the coverage ledger: how much of the catalog applies, what each data layer carries, what is translated outside the catalog, and what is knowingly left Chinese. It is the one file that moves with coverage, so it is updated in the same change as the work whenever a catalog re-import, a new pass or a `REBUILD_PACKAGES` change, a device cycle on the `extra_text` allowlist, or a run whose `text_skipped` / `graphics_skipped` / `append_skipped` is non-empty moves a count. A run's own summary outranks it.
- Consult the record for a pass before changing that pass — why the code is shaped this way, and which attempt already failed, are in its `[S2]`, `[S3]` or journey log rather than in the code — and update it in the same change as the work.
- `docs/runbooks/` holds the procedures: `device-cycle.md` before a device-gated change goes on a phone, `diagnose-untranslated.md` when a string stays Chinese, `read-a-crash.md` when the game dies.
